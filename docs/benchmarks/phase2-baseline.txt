The allocation budget is below the floor the mandated client imposes: a bare
go-redis pipeline of 500 GETs, with no driftwatch code in the path, costs
16.03 allocations per key. TestGetMany500AllocationBudget therefore measures
the floor and driftwatch's GetMany in the same run and asserts on the
difference, which is currently 1.01 per key against a budget of 4. See
docs/DISCOVERIES.md D-007.

BenchmarkScan1M holds one batch plus a bounded duplicate window, never the
whole keyspace. The window is capped at 100,000 keys: remembering every key
of a ten-million-key scan is the unbounded collection 19.2 forbids, and M8
asks in the same breath that such a scan not accumulate all keys in memory.
