driftwatch explain — a materializer that dropped an event

Phase 5 demo (PRD §20 Phase 5), captured against a real Redis:

    $ docker run -d -p 6379:6379 redis
    $ redis-cli SADD block:8e2b41ff replica-1 replica-3
    $ driftwatch explain -f check.yaml --key block:9f3a2c1e --wait 15s

check.yaml is examples/local.yaml with source.type=file pointed at a
captured event stream, so the run is reproducible. The capture holds
replica-0's contiguous sequence 8801..8847 — two adds to block:9f3a2c1e
with forty-five heartbeats between them — and two adds to block:8e2b41ff.

The store was seeded with block:8e2b41ff only. block:9f3a2c1e is the key a
materializer would have dropped: no error anywhere, nothing in any log, and
every existing monitor green.

The load-bearing line is the diagnosis. driftwatch does not say the key is
missing and leave it there: it says it observed replica-0's sequence from
8801 to 8847 with no gaps, so its own view was complete — which is what
makes the target the party that lost something, and names seq 8847 as the
event to look for in the materializer's logs.
