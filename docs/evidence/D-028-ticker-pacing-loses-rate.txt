D-028 — a per-event ticker publishes at a quarter of its requested rate on a
        loaded two-core node, and nothing reports it

Captured Phase 9, while working out why E1's coverage assertion kept landing
just under its threshold on CI and never locally.

======================================================================
WHAT THE CI RUN SHOWED
======================================================================

GitHub Actions run #11, the e2e job, E1 HappyPath:

    [FAILED] coverage was 0.8433: a zero-divergence verdict over that
    fraction of the keyspace is not the reassurance it looks like
    (phase=Watching drift=0 suspect=0 tracked=8556 settled=8192
     coverage=0.8433 targetKeys=8305 applied=12826)

E1 requests 200 events/sec over a 12,000-key keyspace. The check was created
after 2,000 events and the assertion ran roughly 90 seconds later, so about
18,000 events were due to have reached the oracle. 12,826 did — around 70% of
the requested rate, with EventsDropped never in the picture (a later spec
asserts it is zero, and the earlier runs that reached it found it zero).

The publisher was simply not publishing as fast as it had been told to.

======================================================================
THE MECHANISM
======================================================================

The harness paced itself with one ticker tick per event:

    func pacing(rate int) time.Duration {
        if rate <= 200 {
            return time.Second / time.Duration(rate)   // 5ms at 200/sec
        }
        return 5 * time.Millisecond
    }

    ticker := time.NewTicker(pacing(*rate))
    for {
        select {
        case <-ticker.C:
            for i := 0; i < batch; i++ { ...send one event... }
        }
    }

time.Ticker drops ticks it cannot deliver rather than queueing them — its own
documentation says so, and driftwatch's fake clock models the same rule
deliberately. On a two-core GitHub runner where the same node is running
Redis, a materializer, the manager and the test process, a 5ms tick is not
delivered 200 times a second, and every tick that is not delivered is an
event that is never sent and never counted anywhere.

======================================================================
THE MEASUREMENT
======================================================================

Reproduced directly, at GOMAXPROCS=2, requesting 200 events/sec for 10
seconds (2,000 events). "Contended" runs four busy goroutines alongside the
publisher, standing in for the rest of the node. Three consecutive runs:

    run 1
    idle node         per-event ticker:   1991 events (199.1/sec,  100%)
                      elapsed-derived:    2000 events (200.0/sec,  100%)
    contended node    per-event ticker:    482 events ( 48.2/sec,   24%)
                      elapsed-derived:    2003 events (200.3/sec,  100%)

    run 2
    idle node         per-event ticker:   1991 events (199.1/sec,  100%)
                      elapsed-derived:    2000 events (200.0/sec,  100%)
    contended node    per-event ticker:    482 events ( 48.2/sec,   24%)
                      elapsed-derived:    2002 events (200.2/sec,  100%)

    run 3
    idle node         per-event ticker:   1994 events (199.4/sec,  100%)
                      elapsed-derived:    2000 events (200.0/sec,  100%)
    contended node    per-event ticker:    482 events ( 48.2/sec,   24%)
                      elapsed-derived:    2001 events (200.1/sec,  100%)

On an idle machine the two are indistinguishable, which is why this never
showed up locally on sixteen cores. Under contention the ticker delivers a
quarter of what it was asked for, and the elapsed-derived loop delivers all
of it. The real CI node is less saturated than this synthetic load, which is
consistent with the ~70% seen there rather than 24%.

======================================================================
WHY IT MATTERED MORE THAN A SLOW PUBLISHER
======================================================================

Every scenario in the suite is sized against keys/rate. E1's comment reasons
that "12,000 at 200/sec is the same 60 seconds while doing a quarter of the
work"; E2's that "12,000 keys at 150/s is 80 seconds, against a 60-second
detection budget"; E3's that a key made suspect "stays suspect across a
settlement window and a sweep".

A rate silently 30% low makes every one of those cycles 40% longer than the
number written next to it. Nothing fails cleanly. What happens instead is
that scenarios sized with a comfortable margin on paper run without one, and
the failures land on whichever assertion is closest to its threshold —
looking like flakiness, or like a defect in whatever the assertion happens to
be about. E1's coverage was measuring the publisher.

======================================================================
THE FIX
======================================================================

The publisher wakes on a coarse 10ms tick and asks how many events *should*
have gone out by now:

    func owed(elapsed time.Duration, rate int, sent uint64) int {
        due := uint64(elapsed) * uint64(rate) / uint64(time.Second)
        if due <= sent {
            return 0
        }
        return min(int(due-sent), rate)
    }

A dropped tick becomes something to catch up on rather than something lost.
The cap keeps a long stall from turning into one enormous burst.

======================================================================
REPRODUCING
======================================================================

The measurement above is a standalone program; its source is reproduced here
so the number can be checked without the cluster.

    package main

    import ("fmt"; "runtime"; "time")

    const (rate = 200; duration = 10 * time.Second)

    func owed(elapsed time.Duration, rate int, sent uint64) int {
        due := uint64(elapsed) * uint64(rate) / uint64(time.Second)
        if due <= sent { return 0 }
        return min(int(due-sent), rate)
    }

    func work() { s := 0; for i := 0; i < 20000; i++ { s += i }; _ = s }

    func load(stop <-chan struct{}) {
        for i := 0; i < runtime.GOMAXPROCS(0)*2; i++ {
            go func() {
                for { select { case <-stop: return; default: work() } }
            }()
        }
    }

    func ticker() uint64 {
        t := time.NewTicker(time.Second / rate)
        defer t.Stop()
        var sent uint64
        deadline := time.After(duration)
        for {
            select {
            case <-deadline: return sent
            case <-t.C: work(); sent++
            }
        }
    }

    func deadlinePaced() uint64 {
        t := time.NewTicker(10 * time.Millisecond)
        defer t.Stop()
        var sent uint64
        started := time.Now()
        end := time.After(duration)
        for {
            select {
            case <-end: return sent
            case <-t.C:
                for range owed(time.Since(started), rate, sent) { work(); sent++ }
            }
        }
    }

    func main() {
        runtime.GOMAXPROCS(2)
        for _, contended := range []bool{false, true} {
            stop := make(chan struct{})
            if contended { load(stop); time.Sleep(200 * time.Millisecond) }
            a := ticker()
            b := deadlinePaced()
            close(stop)
            fmt.Println(contended, "ticker", a, "derived", b)
        }
    }
